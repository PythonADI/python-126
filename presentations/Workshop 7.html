02

A list that
won’t change.

A list is for things that grow, shrink and shuffle. But some groups are fixed — a point (x, y), a colour (r, g, b), a date. They have a set number of parts, always in the same order.

For those, Python has a tuple — written with round brackets ( ). It looks like a list, but once made it can’t be edited.

[ PART 1 · CAN’T CHANGE ]
04

Try to change it.

A list lets you reassign an item. A tuple refuses — it is locked the moment it’s made.

point = (3, 4) point[0] = 99 # trying to edit
[ Output ]
TypeError: 'tuple' object does not support item assignment

[ Locked on purpose ]This is a feature, not a limit. When a value should never change — a coordinate, a fixed config — a tuple guarantees nobody edits it by accident. Need to change it? Make a new tuple.

[ PART 1 · RETURN MANY ]
06

Return more than one.

A function can hand back several values at once — just separate them with commas. Python packs them into a tuple; you unpack them on the way out.

def min_max(nums): return min(nums), max(nums) # a tuple low, high = min_max([4, 9, 1, 7]) print(low, high) # 1 9
[ Output ]
1 9

return a, b builds a tuple; low, high = ... unpacks it. That’s how one function returns a pair, neatly.

Save it with open.

with open(path, "w") as f: opens a file for writing. Each f.write(...) lands a line in the file — watch it fill in.

Mode "w" means write from scratch — it wipes the file first. The \n (shown as ⏎) is a newline, so each write lands on its own line.

[ PART 2 · THE MODES ]
11

Three modes to know.

The second argument to open(path, mode) decides what you may do.

"r"
→
read an existing fileread · the default
"w"
→
write fresh — erases firstwrite · overwrites
"a"
→
add to the end — keeps the restappend

Careful: "w" wipes the file the instant you open it. To keep what’s there and tack on more, reach for "a" instead.

[ PART 3 · THE CRASH ]
13

One bad input, dead program.

You’ve hit these: a missing dictionary key gives a KeyError; text that isn’t a number gives a ValueError. Either one stops everything.

age = int(input("რამდენი წლის ხარ?\n")) print("next year:", age + 1) # user types "abc" instead of a number...
[ Output ]
ValueError: invalid literal for int() with base 10: 'abc'

The line after never runs. One typo from the user and the whole program falls over. We need a way to catch the error and carry on.

[ PART 3 · TRY / EXCEPT ]
14

Try it. Catch the fall.

Put the risky line in try. The moment it blows up, Python jumps to the matching except instead of crashing — follow the read-head.

try: age = int("abc")except ValueError: print("არ არის რიცხვი")print("...moving on")
executionflow
int("abc")
✗ ValueError
except: match!
print("არ არის რიცხვი")
0 / 4

Name the error you expect — here ValueError. The program keeps running past the block. The same shape catches the KeyError from those “fix the bug” homework tasks.

[ PART 3 · ELSE / FINALLY ]
15

The full four parts.

Catch a missing key, then choose what runs on success and what runs no matter what.

scores = {"nino": 90} try: value = scores["luka"] # risky lookup except KeyError: print("no such student") # ran on error else: print("found:", value) # ran if NO error finally: print("done checking") # always runs
[ Output ]
no such student
done checking

else runs only when the try succeeded; finally runs either way — perfect for cleanup. Both are optional.

[ PART 4 · FILTER & DICTS ]
18

Add an if. Make a dict.

Tack on if to keep only some items. The same idea builds dictionaries with { }.

nums = [-2, 5, -1, 8, 3] positives = [x for x in nums if x > 0] print(positives) # [5, 8, 3] squares = {x: x * x for x in [1, 2, 3]} print(squares) # {1: 1, 2: 4, 3: 9}
[ Output ]
[5, 8, 3]
{1: 1, 2: 4, 3: 9}

if x > 0 filters as it goes. Swap [ ] for { } with a key: value and you get a dict comprehension.
