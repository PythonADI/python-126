Last week a list answered one question: what is at position 2? Perfect when order is the point — a queue, a playlist, a row of scores.

But often you don’t care about position — you care about a name. What is nino’s score? What’s the price of milk? A dictionary looks a value up by a key, not a number.

[ PART 1 · THE PROBLEM ]
03

Two lists, kept in sync.

Storing names and their scores the only way you knew until today — two separate lists, lined up by position:

names = ["nino", "giorgi", "mariami"] scores = [90, 75, 88]

To find giorgi’s score you must first hunt for his index in names, then use that same number in scores. Add or remove one person and the two lists drift out of step. A dictionary ties each name straight to its score: {"nino": 90, "giorgi": 75, "mariami": 88}.

Curly braces, key: value.

Wrap key: value pairs in { }, separated by commas. The key is how you find it; the value is what you get back.

phone = {"nino": "555-1234", "giorgi": "555-9876"} empty = {} print(phone) print(len(phone))

len() counts the pairs, not the letters. And {} is an empty dictionary, ready to be filled — just like [] was last week.

Each key points to a value.

The key is the address; the value is what lives there. So scores["nino"] is 90 — you never say scores[0].

[ PART 1 · LOOKUP ]
06

Reach in by key.

Square brackets again — but this time you put the key inside, not a number.

scores = {"nino": 90, "giorgi": 75, "mariami": 88} print(scores["nino"]) # 90 print(scores["mariami"]) # 88
[ Output ]
90 · 88

It reads almost like English: scores["nino"] — “nino’s score.” The order of the pairs never matters; only the key does.

[ PART 1 · SAFE LOOKUP ]
08

Ask politely: .get()

.get() never crashes. Miss the key and it hands back None — or a fallback you choose.

scores = {"nino": 90, "giorgi": 75} print(scores.get("nino")) # 90 print(scores.get("luka")) # None print(scores.get("luka", 0)) # 0 - the fallback
[ Output ]
90
None
0

The second argument is the default — what to return when the key is absent. That little 0 is the seed of this week’s most important pattern.

[ PART 1 · LIST vs DICTIONARY ]
10

Position, or name?

Same idea — many values in one variable — reached two different ways.

a list — by position
scores = [90, 75, 88] scores[0] # 90 # found by NUMBER # order is the point len(scores) # 3 for s in scores: ...
a dictionary — by name
scores = {"nino": 90} scores["nino"] # 90 # found by KEY # name is the point len(scores) # 1 for k in scores: ...

Reach for a list when order matters and the items are interchangeable; reach for a dictionary when every value has a natural name.

[ PART 2 · ADD & UPDATE ]
12

One line does both.

d[key] = value writes a pair. New key? It’s added. Key already there? It’s overwritten.

scores = {"nino": 90} scores["giorgi"] = 75 # adds a new pair scores["nino"] = 100 # updates the existing one print(scores)
[ Output ]
{'nino': 100, 'giorgi': 75}

There’s no separate “add” and “update” — Python decides for you based on whether the key already exists. Each key appears at most once.

[ PART 2 · MEMBERSHIP ]
15

in checks the keys.

in asks a yes/no question about the keys — perfect for an if. A plain for walks the keys too.

scores = {"nino": 90, "giorgi": 75} if "nino" in scores: print("found nino") for name in scores: print(name)
[ Output ]
found nino
nino
giorgi

A check like "nino" in scores is the safe way to avoid a KeyError — look before you reach in.

[ PART 2 · KEY AND VALUE TOGETHER ]
16

Walk the pairs.

.items() hands you two names at once on every pass — the key and its value.

scores = {"nino": 90, "giorgi": 75, "mariami": 88} for name, score in scores.items(): print(f"{name}: {score}")
[ Output ]
nino: 90
giorgi: 75
mariami: 88

for name, score in ... unpacks each pair into two variables. Want just one side? .keys() gives the names, .values() gives the numbers.

Python · Workshop 06for k, v in d.items()
[ PART 2 · THE CORE PATTERN ]
17

Count things up.

The pattern dictionaries were born for: an empty dict, a loop, and .get(key, 0) + 1 to tally.

words = ["milk", "bread", "milk", "eggs", "milk"] counts = {} for word in words: counts[word] = counts.get(word, 0) + 1 print(counts)
[ Output ]
{'milk': 3, 'bread': 1, 'eggs': 1}

.get(word, 0) is the count so far — 0 the first time a word appears — and + 1 records this sighting. Vote tallies, word frequencies, inventory: all this one shape.

Python · Workshop 06d[k] = d.get(k, 0) + 1
[ PART 2 · LISTS + DICTIONARIES ]
18

Real data, combined.

A list holds the rows; a dictionary holds each row’s fields. This is what real data looks like.

students = [ {"name": "nino", "score": 90}, {"name": "giorgi", "score": 75}, ] for s in students: print(f'{s["name"]}: {s["score"]}')
[ Output ]
nino: 90
giorgi: 75

Loop the list to get one dict per pass, then read its fields by key. A spreadsheet, a contact list, an API response — all just lists of dictionaries.

A grade book, by name.

A dictionary maps each student to a grade. We read it out in Georgian — ქულა means “points,” ჯამში means “in total.”

grades = {"ნინო": 90, "გიორგი": 75, "მარიამი": 88} for name, grade in grades.items(): print(f"{name}: {grade} ქულა") print(f"ჯამში {len(grades)} მოსწავლე")
[ Output ]
